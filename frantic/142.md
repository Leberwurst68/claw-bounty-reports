# Nitrosend Safe Mode — MAP approval loop report

- **Install & commands:** `npm install @nitrosend/cli@0.3.8` (Node v24.21.0, Linux x64) for the MCP tool calls, plus `mailschema` 0.3.2 to validate the extracted description. Safe Mode was switched on with `PATCH /v1/my/account` → `{"safe_mode_enabled":true}`. The campaign was composed with `nitrosend mcp tools call nitro_compose_campaign`, approved with `nitro_control_delivery {operation:"approve"}`, then set live with `{operation:"live",confirm_send_to_all:true}`.
- **Minutes from Safe Mode on to decision:** ~15 minutes. `live` returned `status: awaiting_approval`, `wait_reason: manual_approval`, and the approval email arrived within 30 seconds. The decision itself took one call.
- **Validation:** the `application/ld+json` attachment was pulled byte-exact from the mail and passes `mailschema description 142-description.json --contract contract.json` → `Valid MAP 0.3 description`, digest `sha-256:7db7329fd6d2cc013e01bbf5769e22579c930a17aa619978a6268f341ac7ae02` (see description_json). It names `campaign-send-approval` 0.1, `terms.version` is the digest of the rest of the description, and `terms.id` is the approval URL the receipt points at.
- **Two blockers I hit, with exact errors.** (1) `nitro_control_delivery {operation:"approve"}` fails with `This send isn't ready yet.` until a physical address exists; the real cause is only visible via `nitro_review_delivery`, which returns `physical_address: passed=false` and `CAN-SPAM requires a physical mailing address`. (2) Consuming the approval via REST: `POST /v1/my/map/approvals/131 {"decision":"approve"}` returns **409 `This send changed. Review its current terms before deciding.`** — the decision needs the current `terms.version` echoed in a field named `version` (not `terms_version`, not `terms:{version}`), which returns 200. Neither the error message nor the docs name that field.
- **Doc gap:** nothing documents that the approval endpoint takes `version`, and the 409 message reads like a genuine change rather than a missing argument. Change I would make: accept `terms_version` as an alias and say "pass terms.version as version" in the 409.

Tool: Nitrosend CLI 0.3.8 · mailschema 0.3.2 · Node v24.21.0 · 2026-10-20
