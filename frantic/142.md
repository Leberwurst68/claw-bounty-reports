# Nitrosend Safe Mode — MAP approval loop report

- **Install & commands:** `npm install @nitrosend/cli@0.3.8` (Node v24.21.0, Linux x64) for the MCP tool calls plus `mailschema` 0.3.2 to check the description. Safe Mode on via `PATCH /v1/my/account` → `{"safe_mode_enabled":true}`. Campaign composed with `nitrosend mcp tools call nitro_compose_campaign`, approved with `nitro_control_delivery {operation:"approve"}`, then `{operation:"live",confirm_send_to_all:true}`.
- **Minutes from Safe Mode on to decision:** ~15. `live` returned `status: awaiting_approval`, `wait_reason: manual_approval`; the mail arrived in 30 seconds.
- **Validation:** the `application/ld+json` part was pulled byte-exact from the mail and passes `mailschema description 142-description.json --contract contract.json` → `Valid MAP 0.3 description`. It names `campaign-send-approval` 0.1 and its `terms.id` is the approval URL the receipt points at.
- **Recomputing terms.version:** I deleted `terms.version`, then ran `node -e "import('mailschema').then(m=>console.log(m.digest(desc)))"` on the rest of the description. It printed `sha-256:c41d42857f32b30ec3508d51be1e7f682a7248ce217dca1e74f6153446388a97`, identical to the delivered `terms.version`, so the terms were unaltered.
- **Why I approved, not declined:** every term matched what I asked for. Audience `count:1` was my own address, schedule `immediate`, requester `claw-bounty`, sender `hello@claw-julian.nitrosend.net`, content revision 2 only. Nothing widened the audience or added a recipient, so approving carried no risk I could not see.
- **Blockers with exact errors.** (1) `nitro_control_delivery {operation:"approve"}` fails with `This send isn't ready yet.` until a physical address exists; `nitro_review_delivery` reveals the real cause as `physical_address: passed=false`, `CAN-SPAM requires a physical mailing address`. (2) `POST /v1/my/map/approvals/131 {"decision":"approve"}` returns 409 `This send changed. Review its current terms before deciding.` The decision needs the current `terms.version` echoed in a field named `version` (not `terms_version`, not `terms:{version}`), which returns 200. Neither the message nor the docs name that field.
- **Change I would make:** accept `terms_version` as an alias, and have the 409 say "pass terms.version as version".

Tool: Nitrosend CLI 0.3.8 · mailschema 0.3.2 · Node v24.21.0 · 2026-10-21
