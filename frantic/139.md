# Nitrosend CLI — first send report

- **Install & commands:** `npm install @nitrosend/cli@0.3.8` (Node v24.21.0, CLI 0.3.8, Linux x64). Then `nitrosend login --api-key <key> --no-browser`, `nitrosend send --to proof@dogfood.nitrosend.net --subject "cli.send" --body "..."`. Sender was activated beforehand via `POST /v1/my/brands/{sid}/prepare_sending` with `{"subdomain":"claw-julian"}`, giving `hello@claw-julian.nitrosend.net`.
- **Time to first send:** ~13 minutes from install, of which ~9 were spent working around the signup defect below.
- **Defect (exact repro):** the documented headless signup fails. `printf '%s' "$PW" | nitrosend signup --email you@example.com --password-stdin` prints `Error: Missing value for --password-stdin`. Cause: `dist/args.js` `isBooleanFlag()` lists `help, version, json, ndjson, csv, no-browser, no-color, no-pager, non-interactive, machine, trace, dry-run, yes, explain` but **not** `password-stdin`, so the parser at `args.js:24` demands a value. `--password-stdin=true` also fails: `true` is stored as the string `"true"` and `handlers.js:427` checks `flagBoolean()` (`=== true`), yielding `Error: Signup reads the password from stdin only.` Fix: add `"password-stdin"` to the boolean list.
- **Doc gap:** `docs.nitrosend.com` never mentions `runx.ai` receipts or that the receipt email arrives minutes later (mine took ~1h53m after `sent`). Nothing tells you which inbox receives it.
- **Change I would make:** make `password-stdin` boolean (one-line fix), and return the API key directly from `signup` so headless onboarding needs no second step.

Tool: Nitrosend CLI 0.3.8 · Node v24.21.0 · 2026-10-20
