# Nitrosend SDK — 30-line script report

- **Install & commands:** `npm install @nitrosend/sdk typescript@5.9.3 @types/node` (Node v24.21.0, SDK 0.11.6, TypeScript 5.9.3, Linux x64). Compile with `tsc --strict --target ES2022 --module NodeNext --moduleResolution NodeNext --types node send.ts`, run with `NITROSEND_API_KEY=… node dist/send.js`. Script is 24 lines and reads the key from `process.env.NITROSEND_API_KEY`.
- **Time to first send:** ~6 minutes from install, including two failed run attempts described below.
- **Biggest slowdown (runtime pitfall):** the SDK is ESM-only (`"type": "module"`, `exports` maps only `"import"`). Compiling to CommonJS with default settings and running the output fails with `Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: No "exports" main defined in node_modules/@nitrosend/sdk/package.json`. Setting `"type":"module"` in the project fixed it. Neither README nor docs mention this.
- **Second defect (exact repro):** `ns.messages.send({channel:'email',to,subject,body})` without the second argument throws `idempotency_key is required for live transactional sends`. The README example at line 87 shows `send({...})` with the key marked *optional* in a trailing comment — it is mandatory for live sends. `CreateMessage.idempotencyKey` is also accepted per the types, but the positional argument is the one that works.
- **Doc gap / change I would make:** note the ESM-only requirement and that the idempotency key is required (not optional) in the README send example. Also: `npm install` silently skipped `typescript` while `NODE_ENV=production`, so document the dev-dependency install.
