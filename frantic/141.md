# Nitrosend MCP — self-onboarding report

- **Goal sentence given to the agent:** "Connect the Nitrosend MCP server at https://api.nitrosend.com/mcp, set up a Nitrosend account with a hosted sender, and send a short email to proof@dogfood.nitrosend.net." The agent took the headless API-key path, so no person did an OAuth browser step in this run.
- **Install and commands:** `npm install -g @openai/codex` → `codex-cli 0.163.0` on Node v24.21.0 (Linux x64). MCP wired in `~/.codex/config.toml` as `[mcp_servers.nitrosend] url = "https://api.nitrosend.com/mcp"` with `bearer_token_env_var = "NITROSEND_KEY"`; checked with `codex mcp list`, then one run: `codex exec --skip-git-repo-check --dangerously-bypass-approvals-and-sandbox -C /tmp "<goal>"`. Tools called: `nitro_get_status`, then `nitro_send_message` (channel `email`, `to` proof inbox, subject `mcp.send`).
- **Minutes from connecting to first send:** about 3 minutes, including tool discovery.
- **Client and model:** OpenAI Codex CLI 0.163.0, model `deepseek-v4.1-flash` through the OpenCode Go provider (`wire_api = "responses"`).
- **Where a person was needed:** the account and hosted sender `hello@claw-julian.nitrosend.net` already existed from an earlier headless REST signup, so the only manual step in the whole flow was the first-ever `/v1/signup` (done headless, no browser). In this run the agent needed a person zero times.
- **Slowest step:** MCP tool approval. The first `nitro_send_message` call died with `MCP tool call requires approval, but approval policy is never` — the server was connected and `nitro_get_status` had run fine, but Codex gates mutating MCP tools and nothing in the error names the flag that unblocks it.
- **Defect / doc gap:** Nitrosend's MCP page does not mention that clients with their own per-tool approval gate will silently refuse `nitro_send_message` under `--ask-for-approval never`. Repro: `codex exec --skip-git-repo-check "<goal>"` with the MCP server configured → `nitro_get_status` succeeds, `nitro_send_message` returns the approval error; add `--dangerously-bypass-approvals-and-sandbox` → the same call succeeds.
- **Change I would make:** ship a read-only `nitro_whoami`/`nitro_ping` tool that a client can whitelist, and state on the MCP page which tools are mutating so clients can pre-approve exactly those.
