# mailschema — MAP 0.3 description report

- **Install & commands:** `npm install mailschema` (mailschema **0.3.2**, Node v24.21.0, Linux x64). Validate with `npx mailschema contract contract.json` then `npx mailschema description description.json --contract contract.json`. Both are offline; nothing is uploaded.
- **Time to first valid description:** ~9 minutes, mostly reading the `campaign-send-approval` contract to learn which fields are mandatory.
- **Field I broke and the exact error:** I set `"version": "9.9"` in `type` and `"count": "viele"` in `details.audience`. The CLI printed two lines and exited **0**:
  `/type: names https://mailschema.org/types/campaign-send-approval 9.9, not this contract`
  `/details/audience/count: must be integer`
  Both messages are precise and actionable; the path syntax (`/details/audience/count`) is the strongest part of the tool.
- **Defect — exit code is 0 on validation failure.** The same invalid file returns `EXIT=0`, so any CI step or `&&` chain treats a failed check as success. Only the printed text distinguishes pass from fail. Fix: exit non-zero when any check line is produced. Repro: break any leaf type (e.g. `"must be integer"` above) and run `mailschema description broken.json --contract contract.json; echo $?` → `0`.
- **Doc gap:** the CLI help says `description checks a description and, with --contract, that it uses that contract as it allows`, but never states that a failing check still exits 0, nor that the digest is printed on stdout while errors go to stderr (the `message` subcommand documents the stderr behaviour, the others do not).
- **What I changed:** authored my own `campaign-send-approval` description for a daily briefing mail (`urn:uuid:7c1d4a3e-…`, German, single recipient, sender `brief@openclaw.example`), not the published example. Digest `sha-256:da9a19fe9fb0611cc8de414edb00775a35c3d7e0ff0e3425364357f28667d7a6`.
